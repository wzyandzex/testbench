# 错误码与处理策略（前端）

本文档列出前端对接最常见、最需要特殊处理的错误码。
机器可读错误码契约源：`./contracts/errors.catalog.json`（版本 `2026-03-05.v2`）。

## 1. 统一处理规则

1. 先看 HTTP 状态。
2. 再看响应体 `code`。
3. `code != 0` 一律按失败处理。

统一响应结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

---

## 2. 通用认证错误

| code | HTTP | 含义 | 前端动作 |
|---|---|---|---|
| `401001` | 401 | 未携带 token | 跳登录 |
| `401002` | 401 | token 无效或凭证错误 | 清理本地 token，跳登录 |
| `401003` | 401 | token 过期 | 尝试 refresh，失败则跳登录 |
| `401004` | 401 | refresh token 无效/失效 | 强制重新登录 |
| `403001` | 403 | 权限不足（系统管理员接口常见） | 提示无权限，隐藏入口 |
| `403002` | 403 | 账号未激活 | 引导激活流程 |
| `429001` | 429 | 登录限流 | 提示稍后重试 |

---

## 3. 组织与作用域错误

| code | HTTP | 场景 | 前端动作 |
|---|---|---|---|
| `400` | 400 | 缺少组织上下文 | 检查 `X-Org-ID` 和当前组织选择 |
| `403001` | 403 | 组织管理员权限不足 | 提示“权限不足”，隐藏管理入口 |
| `404001` | 404 | 资源不存在或被权限隐藏（防枚举） | 统一按“未找到”展示 |

---

## 4. Benchmark 业务错误

| code | HTTP | 场景 | 前端动作 |
|---|---|---|---|
| `400001` | 400 | benchmark 名称冲突 | 提示重名，保留表单 |
| `200002` | 200 | 不在待审批状态 | 提示“当前状态不可审批” |
| `200003` | 200 | 无审批权限 | 提示权限不足 |
| `200004` | 200 | 拒绝审批但未传 reason | 表单校验 reason 必填 |
| `200005` | 200 | fork 失败或重复 fork | 提示业务失败原因 |
| `409001` | 409 | 导入同名冲突（create-only） | 提示重名，不做覆盖重试 |

说明：`200xxx` 属于业务错误码，虽然 HTTP 可能是 200，但必须按失败处理。

---

## 5. 导入导出与异步任务

| code | HTTP | 场景 | 前端动作 |
|---|---|---|---|
| `400` | 400 | dataset/参数/文件不合法 | 表单就地提示 |
| `2103` | 400 | URL scheme 不合法（非 http/https） | 阻止提交并提示 |
| `2104` | 400 | URL 命中 SSRF 拦截（私网/非白名单） | 提示“URL 不安全或不受信任” |
| `2105` | 400 | URL 格式非法 | 提示用户修正 |
| `503` | 503 | Kafka 队列不可用或依赖服务不可用 | 提示稍后重试 |
| `500` | 500 | 后端内部错误 | 保留操作上下文并允许重试 |

---

## 6. 系统管理接口（Kafka/SWE 全局能力）

以下接口典型会返回 `403001`：

- `/api/v1/kafka/*`
- `/api/v1/swenbench/ws`
- `/api/v1/swenbench/ws/stats`
- `/api/v1/swenbench/repo/cache`（GET/DELETE）

前端建议：

1. 非系统管理员直接隐藏入口。
2. 即使隐藏也保留 `403001` 兜底提示。

---

## 7. 推荐错误提示分层

1. 业务错误（`code!=0`）：优先展示后端 `message`。
2. HTTP 错误（4xx/5xx）：展示通用错误文案 + 重试入口。
3. 网络错误（超时/断网）：展示“网络异常，请稍后重试”。
